# qCMS — نموذج تصميم تجريبي

بروتوتايب لنظام إدارة المراسلات والمعاملات. عربي من اليمين للشمال، مكتوب HTML و CSS و JavaScript عادي، من غير أي framework.

ده نموذج للعرض بس. مفيش backend ولا بيانات حقيقية.

---

# طريقة الشغل

الكلام ده موجّه لأي حد هيشتغل على المشروع. اقراه كله مرة واحدة قبل ما تبدأ، وبعد كده هيبقى واضح.

## الفكرة في سطرين

كل واحد بينزّل نسخة من الملفات، يشتغل على التاسك بتاعه على جهازه، وبعدين يرفع الملفات اللي غيّرها بس. وفي الآخر إحنا بنجمع شغل الكل مع بعض على GitHub.

## قبل ما تبدأ التاسك

**نزّل نسخة جديدة من الملفات.**

افتح الريبو، اضغط زرار **Code** الأخضر فوق على اليمين، واختار **Download ZIP**. فك الضغط على جهازك.

مهم تنزّل نسخة جديدة قبل كل تاسك. لو فضلت شغال على نسخة من أسبوع، الملفات اللي معاك تبقى قديمة، ولما ترفعها ممكن تمسح شغل غيرك.

## وانت بتشتغل

اشتغل عادي على جهازك. عشان تشوف الموقع، شغّل الأمر ده جوه فولدر المشروع:

```
node serve.js
```

وبعدين افتح `http://localhost:8770/site/index.html` في المتصفح.

## بعد ما تخلص

**1. اعرف إيه اللي اتغير**

لو شغال مع Claude Code، اسأله: «إيه الملفات اللي اتغيرت؟» وهو هيقولك الأسامي.

**2. حدّث ملف التسليم**

افتح `HANDOFF-qCMS.md` واكتب سطر أو اتنين عن اللي عملته، والتاريخ. ده مش اختياري. الملف ده هو اللي بيخلي أي حد يقدر يكمّل بعدك ويعرف ليه كل حاجة اتعملت بالشكل ده.

**3. ارفع الملفات**

افتح الريبو على GitHub. ادخل الفولدر اللي فيه الملفات اللي غيّرتها — غالبًا فولدر `site`. لو صور، ادخل `site` بعدين `assets`.

وانت جوه الفولدر الصح، اضغط **Add file** وبعدين **Upload files**، واسحب الملفات اللي غيّرتها بس. مش الفولدر كله.

**4. اختار قاعدة جديدة**

تحت الصفحة هتلاقي اختيارين. اختار التاني:

«Create a new branch for this commit and start a pull request»

اكتب اسم يوصف التاسك بتاعك — مثلاً `dashboard-fix` أو `new-colors` — واضغط **Propose changes**.

ده بيعمل طلب دمج، مش تعديل مباشر على الكود الأساسي. يعني لو فيه غلطة نقدر نشوفها قبل ما تدخل.

**5. استنى المراجعة**

واحد من الفريق هيبص على الشغل، ولو كله تمام هيضغط **Merge** وشغلك يدخل مع شغل الباقيين.

# قواعد لازم تتحط في الدماغ

## كل واحد مسؤول عن ملفاته

قبل ما تبدأوا، اتفقوا مين هياخد أنهي ملف. التقسيم ده مجرد اتفاق بينكم، مش حاجة تتكتب في الكود.

ليه؟ لأن لما ترفع ملف من المتصفح، GitHub بيستبدل النسخة القديمة منه بالكامل. فلو اتنين اشتغلوا على نفس الملف، اللي يرفع تاني هيمسح شغل الأول — ومن غير أي تحذير.

طول ما محدش بيلمس ملف التاني، مفيش أي مشكلة.

## ملف `index.html` مشترك

ده الملف الوحيد اللي الكل محتاجه، لأن كل الماركب جواه. القاعدة: **واحد بس يرفعه في المرة**. لما يخلص ويتعمل Merge، اللي بعده ينزّل نسخة جديدة وبعدين يرفع.

ولو محتاج تضيف فيه حاجة، ضيفها في **آخر** القسم المناسب. ما تعيدش ترتيب حاجة موجودة وما تغيّرش مسافات في أسطر مش بتاعتك.

## ما تغيّرش اسم أي ملف

الأسامي ثابتة. `index.html` بينده على الملفات بأساميها، فلو غيّرت اسم أي واحد فيهم الموقع هيقف عن الشغل.

## ارفع اللي غيّرته بس

نزّل كل حاجة، بس ارفع الملفات اللي لمستها فعلاً. لو رفعت الفولدر كله، هترفع معاه ملفات زمايلك بالنسخة القديمة اللي عندك، فتمسح شغلهم.

## ما ترفعش الملفات المولّدة

في المشروع فولدرات بتتعمل أوتوماتيك: `src` و `deploy` و `deploy-public` وملف `site/qcms-inbox.html`.

دي معمولها تجاهل عن قصد ومش موجودة في الريبو. سبب ده إن `qcms-inbox.html` حجمه حوالي 9 ميجا وبيتغير بالكامل مع أي تعديل، فلو كان مرفوع كان هيعمل تعارض في كل مرة.

لو محتاج تولّدهم عندك للنشر، شغّل:

```
node sync.js
```

بس ده وقت النشر فقط، مش مع كل رفع.

# قواعد الكود

دي قواعد من المستخدمة، مش قابلة للتفاوض:

**استخدم نفس الكومبوننت الموجود.** قبل ما تضيف أو تعدّل أي حاجة، شوف الحاجة الشبيهة معمولة إزاي واستخدم نفس الكلاسات ونفس قاعدة الـ CSS. ضم السيليكتور بتاعك للقاعدة الموجودة بدل ما تعمل قاعدة جديدة بنفس القيم.

**السكرول بار ما ياخدش مكان أبدًا.** يظهر فوق المحتوى وقت السكرول بس.

**سطر «موقع حكومي رسمي» ما يتنشرش.** في أي نسخة منشورة بيتبدل بـ «نموذج تصميم تجريبي — qCMS». الملفات المحلية فيها السطر زي ما هو.

**الألوان من الـ tokens.** كلها معرّفة في `:root` جوه `styles.css`. ما تكتبش قيمة hex في نص الكود.

**الأيقونات الجديدة تتحط في `ICONS`** جوه `icons2.js`، مش inline في الماركب.

# الملفات وبتعمل إيه

كل الكود جوه فولدر `site`:

| الملف | بيتحكم في إيه |
|---|---|
| `index.html` | الماركب بتاع كل حاجة — كل الصفحات والمنيوهات والبانلات |
| `app.js` | البريد: ليستة الإيميلات، الإيميل المفتوح، الفولدرات |
| `styles.css` | ستايل البريد والشكل العام للموقع |
| `dashboard.js` | الصفحة الرئيسية: الأرقام والرسوم البيانية |
| `dashboard.css` | ستايل الصفحة الرئيسية |
| `popovers.js` | المنيوهات، الإشعارات، الملاحظات، شات Qemam AI |
| `popovers.css` | ستايل المنيوهات والبانلات والشات |
| `rules.js` | قواعد البريد (زي Outlook) |
| `login.js` | شاشة الدخول وبوب أب الترحيب |
| `login.css` | ستايل شاشة الدخول |
| `icons.js` و `icons2.js` | كل الأيقونات، مخزّنة في object اسمه `ICONS` |
| `assets/` | الصور والأيقونات |

وبرّه فولدر `site`:

| الملف | بيعمل إيه |
|---|---|
| `serve.js` | سيرفر بسيط عشان تفتح الموقع محليًا |
| `sync.js` | بيولّد النسخ المنشورة. وقت النشر بس |
| `build-single.js` | بيعمل نسخة الملف الواحد. `sync.js` بينده عليه |
| `HANDOFF-qCMS.md` | كل تاريخ المشروع والقرارات. اقراه قبل ما تبدأ |

# لو عندك Git متسطّب

لو مرتاح مع Git، الشغل أسهل وأأمن — لأن Git بيدمج السطور اللي اتغيرت بس، مش الملف كله.

```
git clone https://github.com/tprky97/qcms-prototype.git
```

قبل كل تاسك:

```
git checkout main
```

```
git pull
```

```
git checkout -b feature/اسم-التاسك
```

بعد ما تخلص:

```
git add .
```

```
git commit -m "وصف قصير للي اتعمل"
```

```
git push -u origin feature/اسم-التاسك
```

وبعدين افتح Pull Request من الريبو.

لو شغال مع Claude Code، تقدر تقوله الكلام ده بالعربي وهو ينفّذه: «هات آخر تحديثات» أو «ارفع الشغل ده واعملي PR».
